Section 01
The Full User Journey

This is the complete path a user takes — from opening FileFlow for the first time, to having a clean, organised file system. Every step is mapped. Nothing is skipped.

The design goal: a 3rd grader or a grandmother should be able to use this without reading a manual. FileFlow does the thinking. The user just approves.

1
Open FileFlow
User opens the app. Sees the welcome screen. FileFlow greets them by name and explains itself in one sentence. No jargon.
SCREEN: Welcome
2
Tell FileFlow what to do (or just click a chip)
User types naturally — "clean my downloads" — or clicks one of the quick-start chips. FileFlow understands plain English. No commands.
SCREEN: Chat
3
FileFlow scouts the folder (READ ONLY)
FileFlow scans everything. Nothing moves. It produces a Scout Report showing what it found — totals, categories, nest depth. User sees this before anything happens.
SCREEN: Scout Report
4
User scopes the job
FileFlow asks: "Do you want me to tackle just the job applications first, or everything?" User picks. FileFlow never assumes.
SCREEN: Scope Selection
5
FileFlow shows the Plan
FileFlow lays out exactly what it will do — which files move where, what gets archived, what gets deleted. User reads it like a shopping receipt before paying.
SCREEN: Plan Review
6
User approves (or edits) the Plan
User clicks "Approve & Run". Or edits specific items. Or cancels. FileFlow will not move a single file until this step is completed.
SCREEN: Plan Review
7
Action Popup opens — FileFlow runs
The popup window appears. FileFlow works through the queue in real time. User can watch, pause, or stop at any moment. The chat stays open behind the popup.
POPUP: Running
8
Run completes — Summary shown
Popup transitions to a Done state. Shows: files moved, duplicates removed, space freed, time taken. One-click undo available for 24 hours.
POPUP: Done
9
FileFlow reports back in chat
Popup closes. FileFlow sends a summary message in the chat. Asks if the user wants to tackle the next chunk, or schedule a recurring cleanup.
SCREEN: Chat
10
User can undo anytime (up to 24h)
From the chat, user can say "undo that" and FileFlow restores everything from the archive. Full rollback. No file is permanently lost until the user explicitly clears the archive.
SCREEN: Chat
Section 02
Every Screen Defined

FileFlow has 6 distinct screens/states. Each one has a clear job. No screen does two things at once.

S1
Welcome Screen
SCREEN

Shows on first open and after each completed session. FileFlow introduces itself in one plain sentence. Offers 4 quick-start chips. Nothing else on screen — no clutter, no options, no confusion.

User action: Type a message or click a chip.
FileFlow action: Move to Scout.

S2
Folder Picker
SCREEN

If the user doesn't specify a folder, FileFlow asks with a simple folder browser popup. The user clicks their folder — that's it. No typing paths. No confusion.

Appears when: User says "clean my stuff" without specifying where.
FileFlow says: "Which folder should I look at? Click the 📂 button to pick one."

S3
Scout Report (in chat)
SCREEN

Appears as a card inside the FileFlow chat bubble. Shows totals, categories as bars, and nest depth. Always read-only — makes clear nothing has moved yet. Big reassurance message underneath.

Key message to user: "I've looked but haven't touched anything yet."
Buttons shown: Scope options (jobs only / everything).

S4
Plan Review (in chat)
SCREEN

The most critical screen. Shows every action FileFlow intends to take, grouped by type: CREATE folders, ARCHIVE duplicates, MOVE files, PURGE empty folders. Each item is readable by a non-technical person.

Buttons: Approve & Run / Edit Plan / Cancel.
Rule: No run can start without explicit approval on this screen.

S5
Action Popup (Running)
SCREEN

A modal window that opens over the chat when a run starts. Live progress bar, live file counter, scrollable action log (Done / In Progress / Pending). Pause and Stop buttons always visible.

Key principle: User can always stop. FileFlow never locks them out.
Closes: When user clicks X or run completes.

S6
Run Complete Summary
SCREEN

Popup transitions to a "Done" state with a clean summary: files moved, duplicates removed, space freed, time taken. Green checkmark. One-click undo button prominent. Option to export the run report.

FileFlow says in chat: Summary + "Want me to tackle the next batch or schedule a weekly cleanup?"

Section 04
All 7 Popup States

The action popup is the most technically complex part of FileFlow. It must handle 7 distinct states. Each state has a different appearance, different controls, and a different message.

State 1 — Idle / Not Open
Popup doesn't exist yet. Chat is full screen. This is the default state before any run is approved.
Shows: Nothing. Only the chat.
State 2 — Preparing
Popup opens. FileFlow is doing the final pre-run checks — archiving originals, building the target folder structure. Progress bar at 0%. No files have moved yet.
Shows: "Getting ready..." · Progress 0% · No Pause/Stop yet (prep is fast)
State 3 — Running
Files are actively moving. Progress bar fills. Live counter shows files moved. Action log scrolls with Done / Running / Pending items. Pause and Stop buttons are active.
Shows: Live bar · File counter · Scrollable log · ETA · Pause + Stop
State 4 — Paused
User clicked Pause. Current file finishes safely. Everything else waits. The popup stays open. No data loss. User can resume or stop from here.
Shows: "Paused" banner · Resume button · Stop button · Log frozen
State 5 — Stopped Mid-Run
User clicked Stop, or an error occurred. FileFlow immediately stops. Shows a clear summary of what was done and what wasn't. Archive is intact. Undo is available.
Shows: What completed · What didn't · Undo button · "Continue from here" option
State 6 — Done (Success)
All files processed successfully. Popup turns to a green-tinted summary view. Big clear numbers: files moved, duplicates removed, space freed. Undo button is prominent.
Shows: ✓ Summary stats · Undo (24h) · Export report · Close button
State 7 — Error
Something unexpected happened (e.g. file locked by another program, disk full, permission denied). FileFlow stops safely. Shows exactly which file caused the problem and why, in plain English.
Shows: What went wrong (plain English) · What was completed · Undo · Retry option
⚠️
Critical rule for all popup states: The "X" close button and the "Undo" button must be visible in every single state. The user must never feel trapped inside a running process with no way out.
Section 05 — 07
All 4 Edge Cases

You selected all four. Smart — these are the cases that break tools and destroy user trust. Here is how FileFlow handles each one gracefully.

⚠️ Edge Case 1 — Misidentified File
FileFlow thinks a file is a job application, but it's actually something else — a personal letter, a contract, a course certificate. It's going to move it to the wrong place.
How FileFlow handles it
Any file below a confidence threshold goes to the Review Queue — never auto-moved. In the Plan Review screen, these appear as yellow "UNCERTAIN" items. User sees: "I'm not sure what this is — can you tell me?" with the filename and a dropdown to classify it. After 3 confirmed corrections, FileFlow learns and never asks again for that pattern.
💥 Edge Case 2 — Crash Mid-Run
The computer crashes, power cuts out, or FileFlow itself crashes while in the middle of moving 3,000 files. Half the files moved, half didn't. The user doesn't know what state their system is in.
How FileFlow handles it
Every completed action is written to an audit log in SQLite before the next action starts. On restart, FileFlow reads the log and shows: "It looks like I was interrupted. Here's what completed and what didn't. Want me to continue from where I left off, or undo everything?" Archive is always intact — original files are never deleted until moves are verified.
🔄 Edge Case 3 — User Changes Mind Halfway
FileFlow is 60% through a 3,000 file run. The user realises they approved the wrong plan — maybe they wanted to keep a specific employer's files separate, or they don't want the duplicates archived.
How FileFlow handles it
User clicks Pause, then Stop. FileFlow shows: "Stopped at 1,847 of 3,241 files. Here's what was done. You can: (A) undo everything that ran, (B) keep what's done and adjust the plan for the rest, or (C) continue as-is." All three paths are safe. Nothing is permanent until the archive is cleared.
⚡ Edge Case 4 — Two Runs Conflict
The user starts a run on Downloads, then accidentally starts another run on the same folder. Or the job application automation system is actively creating files in the same folder FileFlow is reorganising.
How FileFlow handles it
FileFlow places a lightweight lock file in any folder it's currently working on. If a second run tries to touch the same folder, it waits and shows: "Another FileFlow session is already working in this folder. I'll start when it's done." For external programs (like the job automation system), FileFlow detects files modified in the last 60 seconds and skips them automatically, flagging them as "ACTIVE — skipped" in the log.
Section 08
The Golden Rules

These rules cannot be broken by any feature, shortcut, or user request. They are the foundation of user trust.

Non-negotiable rules — baked into the core
🔒
Archive before act. FileFlow backs up the original state of every file before touching it. A file is only permanently changed after the move is verified AND the user has had 24 hours to undo.
👁️
Show before do. Every single action must be shown in the Plan Review screen and approved by the user before it runs. No exceptions. No auto-runs. No "trust me".
🚫
Never delete without permission. FileFlow moves to archive. It never permanently deletes anything unless the user explicitly goes to the archive and says "clear this". Even duplicates go to archive, not trash.
⏸️
Always stoppable. The user can pause or stop at any moment. FileFlow will finish the current file safely and then stop. The user is never locked out of their own system.
🤔
Uncertain = ask, never guess. If FileFlow isn't confident about what a file is or where it belongs, it asks. It never makes a guess silently. Uncertain files go to the Review Queue.
🔁
Full undo, always. Every run produces a complete undo package. One click restores everything to its pre-run state. This remains available for 24 hours after each run.
👵
Plain English only. No file paths in messages. No technical jargon. No error codes. If something goes wrong, FileFlow says what happened and what to do next, in the simplest possible words.
Section 09
Component Map

Every piece that needs to be built, what it does, what technology powers it, and what order to build it in.

Build Order Component What It Does Technology Depends On
1 Recursive Scanner Walks every folder to any depth. Builds a full file tree in memory. Read only. Python · pathlib · os.walk —
2 Audit Log (SQLite) Records every action taken. Powers undo, crash recovery, and run reports. Python · sqlite3 —
3 File Classifier Reads filename, extension, folder path, and content to assign a category. Returns a confidence score. Python · regex rules · Claude API (fallback) Scanner
4 Entity Extractor Pulls the "who" from a filename — e.g. "John Smith Attorneys". Groups files by employer or origin. Python · regex · NLP Classifier
5 Duplicate Detector Compares files by hash + timestamp. Labels: ORIGINAL, DUPLICATE, VERSION, UNCERTAIN. Python · hashlib (MD5) Scanner
6 Plan Builder Takes the classified file tree and produces a structured list of actions. Does not execute. Python · pure logic Classifier · Entity Extractor · Duplicate Detector
7 Archive Engine Before any move, copies original files to a timestamped archive folder with path metadata logged to SQLite. Python · shutil · sqlite3 Audit Log · Plan Builder
8 Action Engine Executes the approved plan: creates folders, moves files, purges empty directories. Verifies each move before proceeding. Python · shutil · pathlib Archive Engine · Audit Log
9 Rollback Engine Reads the audit log and restores all files to their original locations from the archive. Python · sqlite3 · shutil Audit Log · Archive Engine
10 UI — Chat Interface The main window. Chat bubbles, scout report cards, plan review cards, quick chips, input bar. HTML · CSS · JS (bundled via Pywebview or Electron) All backend components
11 UI — Action Popup The modal window. All 7 states. Live progress bar. Action log. Pause / Stop / Undo controls. HTML · CSS · JS · WebSocket to Python backend Action Engine · UI Chat
12 Lock Manager Prevents two runs from touching the same folder simultaneously. Detects files modified by external programs in the last 60 seconds and skips them. Python · file locks Action Engine
13 Review Queue Collects files the classifier is uncertain about. Presents them to the user for manual classification. Learns from corrections. Python · sqlite3 · UI Classifier · UI
14 Behavior Memory (v2) Learns patterns over time — files to always skip, recurring downloads, user preferences. Asks permission before applying learned behaviors. Python · sqlite3 All of the above
✅
Recommended build order: Build components 1–6 first (the brain). Test them in the terminal with no UI. Only then add the UI (10–11) on top. This way, if anything breaks, you know it's a UI problem not a logic problem.
